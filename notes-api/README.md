# Notes API

Учебный REST API для заметок на чистом `node:http` — без фреймворков и зависимостей. Свой роутер, цепочка middleware в стиле Koa, хранение в JSON-файле.

## Запуск

Требуется Node.js >= 26 (TypeScript запускается напрямую, без сборки).

```bash
cp .env.example .env
npm start
```

## Переменные окружения

| Переменная     | По умолчанию          | Описание                    |
| -------------- | --------------------- | --------------------------- |
| `PORT`         | `3000`                | Порт сервера                |
| `CORS_ORIGINS` | `*`                   | Разрешённые origin для CORS |
| `DATA_FILE`    | `./data/notes.json`   | Файл с заметками            |
| `BASE_URL`     | `http://localhost`    | Базовый URL                 |
| `CLUSTER`      | `false`               | Запуск воркеров по числу CPU |

## Эндпоинты

| Метод    | Путь           | Описание                                   |
| -------- | -------------- | ------------------------------------------ |
| `GET`    | `/health`      | Проверка работоспособности                 |
| `GET`    | `/notes?q=`    | Список заметок, `q` — поиск по заголовку   |
| `GET`    | `/notes/:id`   | Одна заметка                               |
| `POST`   | `/notes`       | Создать заметку (`201` + `Location`)       |
| `PATCH`  | `/notes/:id`   | Частично обновить заметку                  |
| `DELETE` | `/notes/:id`   | Удалить заметку (`204`)                    |

Тело `POST`/`PATCH` — JSON с полями `title` и `content` (строки 1–10 000 символов; в `PATCH` достаточно одного поля). Лимит тела запроса — 1 МБ.

```bash
curl -X POST localhost:3000/notes \
  -H 'content-type: application/json' \
  -d '{"title":"Hello","content":"World"}'
```

## Ошибки

Все ошибки возвращаются в едином формате:

```json
{ "error": { "code": 422, "message": "Unprocessable entity", "details": ["title"] } }
```

Коды: `400`, `404`, `405`, `413`, `415`, `422`, `500`.

## Устройство

- **Middleware** (`src/middleware`): `respond` → `requestId` → `logger` → `errorHandler` → `cors` → `body` → `router`
- **Request ID**: берётся из заголовка `x-request-id` или генерируется, возвращается в ответе
- **Хранение**: заметки в памяти, запись в файл через очередь — без гонок при параллельных запросах
- **Graceful shutdown**: по `SIGINT`/`SIGTERM` сервер дожидается текущих запросов (до 10 с)

## Cluster: замеры

| Эндпоинт       | Без cluster             | С cluster                |
| -------------- | ----------------------- | ------------------------ |
| `GET /health`  | 18 836 rps, p99 7 ms    | 63 062 rps, p99 3 ms     |
| `GET /notes`   | 5 850 rps, p99 27 ms    | 18 003 rps, p99 11 ms    |

**Запись в cluster-режиме ломается.** Каждый воркер — отдельный процесс со своей копией заметок в памяти и своей очередью записи. Очередь упорядочивает запись только внутри одного процесса, поэтому воркеры перезаписывают файл целиком своей версией данных: заметка, созданная одним воркером, теряется при следующей записи другого, а чтение с разных воркеров возвращает разные данные. Для корректной записи нужно общее хранилище (БД) или запись через primary-процесс.
